The incident began at approximately 02:00 AM UTC when the primary load balancer started reporting 502 Bad Gateway errors for the main API endpoints. Upon investigation, it was discovered that the backend payment processing service had run out of memory due to a memory leak in the latest deployment. The service was rolled back to the previous stable version, and traffic stabilized at 02:45 AM UTC. No customer data was lost, but roughly 500 transactions failed during the outage.
